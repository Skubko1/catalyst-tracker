# catalyst-tracker

Ботоподобный трекер крипто-**катализаторов** — событий, которые двигают цену
(разлоки, ETF-заявки, governance-апгрейды, buyback/burn, листинги). Собирает их
в размеченную SQLite-БД и меряет **абнормал-ретёрн** вокруг каждого события, чтобы
отделить реальный сигнал от рыночной беты.

Это слой «**когда**» из двухслойной идеи: dev-активность отвечает «кто вообще
способен родить катализатор» (медленный скрин), а этот трекер — «когда он прилетит».

## Два типа катализаторов = две архитектуры

| | Календарь | Ватчер |
|---|---|---|
| Природа | дата известна заранее | ловишь в момент появления |
| Пример | разлок, дедлайн ETF-решения | новый филинг, burn-tx, листинг |
| Запуск | крон раз в час, **stateless** | крон каждые 2–5 мин, **backfill-on-restart** |
| Эдж | окно ожидания (рынок отыгрывает заранее) | скорость реакции |
| Даунтайм | безопасен | дыра в датасете → догон обязателен |

Почти весь предсказуемый эдж — в календаре: событие датировано, а рынок отыгрывает
его **до** факта (эталон priced-in / sell-the-news — одобрение ETF).

## Принципы
- **Ончейн-первый.** Чем ближе источник к он-чейн-правде, тем меньше фейков.
  PR — только верхний шумный слой (Tier 3), ядро на ончейне и структурированных
  датах (Tier 1–2).
- **Прайор зашит в тип события** (`config.mjs`), не угадывается по факту: разлок →
  bearish, buyback/burn → bullish, листинг → spike_fade, ETF-решение → ambiguous.
  Без этого event-study смешает всё в кашу.
- **Дедуп по `(detector, external_id)`** — один катализатор не задваивается.
- **Look-ahead под контролем**: пишем `announce_ts` (когда стало публично)
  отдельно от `event_ts` (когда бьёт); study пропускает неотыгравшееся.

## Структура
```
config.mjs              тиры, прайоры, источники, тюнинг
src/
  db.mjs                SQLite: схема, дедуп-upsert, watermarks (движок изолирован)
  notify.mjs            Telegram (фолбэк в консоль)
  registry.mjs          реестр детекторов
  run-calendar.mjs      крон календарного слоя (stateless)
  run-watchers.mjs      крон ватчеров (с backfill-on-restart)
  detectors/
    _base.mjs           fetch + фабрика нормализованного события
    unlocks.mjs         ✅ эталон: разлоки (DefiLlama)
    edgar.mjs           ⬜ заглушка: ETF-заявки SEC EDGAR
    onchain-burn.mjs    ⬜ заглушка: buyback/burn по RPC
analysis/
  run-study.mjs         event-study по абнормал-ретёрнам
```

## Старт
```bash
npm install                    # ставит better-sqlite3
cp .env.example .env           # впиши Telegram-токен (или оставь пустым — лог в консоль)
npm run selftest               # оффлайн-проверка парсера разлоков (без сети и БД)
npm run init-db                # создать схему
npm run calendar               # собрать календарь (разлоки)
```
> `better-sqlite3` — единственная native-зависимость. Обычно ставится
> прекомпилированным бинарником. Если сборка на Windows заартачится — можно
> перейти на встроенный `node:sqlite` (флаг `--experimental-sqlite`); менять
> придётся только `src/db.mjs`, движок там изолирован.

## Сверка источника
Форму ответа DefiLlama не удалось проверить вживую при сборке. Перед первым
прогоном:
```bash
node src/detectors/unlocks.mjs --inspect   # покажет сырую форму ответа
```
Если имена полей отличаются — поправь только `mapProtocol()` в `unlocks.mjs`.
Логика нормализации/дедупа/study от этого не зависит.

## Роадмап (по приоритету ботабельности)
1. ✅ **Разлоки** — самый дешёвый, полностью структурирован, ясный прайор.
2. ⬜ **EDGAR** — ETF-заявки: бесплатно, дедлайны решений дают форвардный календарь.
3. ⬜ **Ончейн burn/buyback** — событие с tx-пруфом, ноль зависимости от PR.
4. ⬜ Прайсовый загрузчик (CoinGecko history) → наполнить `prices` для study.
5. ⬜ Point-in-time состав топ-200 (включая мёртвых) — против survivorship.

## Дисклеймер
Исследовательский инструмент, не финансовый совет. Конкретные эндпоинты, лимиты
и тарифы API меняются — сверяйся с актуальной докой (напр. ребренд
TokenUnlocks → Tokenomist).
